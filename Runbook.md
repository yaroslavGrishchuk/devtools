# Runbook

Короткие правила работы с репозиторием, которые команда соблюдает всегда.

## Перед push: git status clean

- **Правило:** перед каждым `git push` проверять, что рабочая копия чистая — нет незакоммиченных изменений и нет
  случайных untracked-файлов.
- **Где проверять (симметрия UI/CLI):**
    - **IDE:** Commit Tool Window (`Ctrl+K` / `Alt+0`) → список Local Changes **пуст**.
    - **CLI:** `git status` → `nothing to commit, working tree clean`.
- **Если статус не clean:**
    - сущностные изменения — закоммитить;
    - мусор (IDE/OS/Gradle) — добавить паттерн в `.gitignore` и убрать из индекса через `git rm --cached` (без удаления
      с диска), затем отдельный санитарный коммит.
- **Расхождение UI и CLI** (Commit Tool Window показывает не то же, что `git status`) — сигнал разобраться: новые
  артефакты, настройки IDE, `.git/info/exclude`, глобальный `.gitignore`.

Этот документ описывает, как поддерживать качество кода в проекте с помощью автоматических проверок и что делать, если они падают.
